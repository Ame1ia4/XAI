# What each experiment should measure?
- Runtime
- Stability
- Fidelity

## Runtime:

- Import time and print after each Explainer

- You measure how long LIME takes.

- Python makes this easy:

```
importtime
```

Then:

```
start=time.perf_counter()exp=explainer.explain_instance(data_row=instance.values,predict_fn=model.predict_proba,labels=(predicted_class_index,),num_features=5,num_samples=5000
)runtime=time.perf_counter()-startprint("Runtime:",runtime)
```

Now you have:

```
num_samples    runtime
500             0.2 sec
1000            0.4 sec
2500            1.0 sec
5000            2.1 sec
10000           4.0 sec
```

Your exact values will depend on your machine.

## Stability:

How can you measure stability?

- A relatively simple approach for your project is to compare the LIME feature weights across repeated runs.

- For example, run LIME **5 times** for each sample budget:

```
500 samples     → 5 explanations
1,000 samples   → 5 explanations
2,500 samples   → 5 explanations
5,000 samples   → 5 explanations
10,000 samples  → 5 explanations
```

Then calculate how similar the explanations are.

One useful measure is **Spearman rank correlation** between the feature-weight vectors.

You could also measure whether the same top 5 features appear each time.

*For example:*

```
Budget       Top-5 agreement
500          0.62
1,000        0.74
2,500        0.88
5,000        0.94
10,000       0.96
20,000       0.96
```

That would be a very interesting result.

## Fidelity:

> Is that simple surrogate actually representing what the Random Forest is doing? 

LIME provides a local explanation score that can be used as a fidelity measure.

*You can inspect:*

```
exp.score
```

after generating an explanation.

For example:

```
print(exp.score)
```

  - `lime_study/notes/design_decisions.md`: every parameter value and why.
- Today we also justified the new d = 50 condition in the older docs and fixed overlapping labels in the figures.
- **Status: the full study has not been run with the new code yet.** The saved full results in `lime_study/results/` are from the old design (20-10-2026) and must **not** go into the paper.

## What changed in the study design
- **Fidelity is now measured out of sample.** LIME's own `explanation.score` is scored on the same samples the surrogate was fitted to, so small budgets looked artificially good. In the old results, Logistic Regression's fidelity *fell* as N rose. It is replaced by:
  - **held-out surrogate fit** (kernel-weighted R²) and **held-out surrogate error** (RMSE), both on 5,000 fresh perturbations per case × d;
  - the old score, kept as `fidelity_insample` for comparison only.
- **Flat outputs.** When a model's probability barely moves near a case (SD < 0.01), R² breaks down. Those cases are flagged `flat_output` and left out of R², while RMSE is still reported.
- **Convergence as well as repeatability.** Each explanation is now also compared with two **large-N reference explanations** (N = 50,000) using top-5 Jaccard.
  - The **reference ceiling** is how well the two references agree with each other. No normal run can be expected to beat it.
  - **Relative agreement** divides by the ceiling.
  - A reference only counts if the two agree on at least 4 of their top 5 features (0.667). This rule was set before any results.
- **Repeat Jaccard is kept** as the stability measure (Spearman was dropped on 20-10-2026). Only claim "LIME is less stable at higher d" if **both** repeat Jaccard and relative agreement fall.
- **Every model explains the same class:** the row's true class. Before, models sometimes explained different classes for the same row.
- **N ≤ d is flagged as a low sample-to-feature ratio** (`low_sample_ratio`, first called "underdetermined" and renamed in fix 23, because LIME's ridge always has a unique solution) and kept out of trend lines. In the full sweep only N = 500 at d = 500 qualifies.
- **30 explained cases (5 per class), up from 18 (3 per class),** so the confidence intervals are more reliable.
- **New feature count: d = 50,** so the sweep is now 50 / 100 / 300 / 500 (see below).
- **Sensitivity variants:**
  - `ranked_subset` picks the most informative features instead of a random subset;
  - `fixed_kernel` holds LIME's kernel width constant across d.

  A d-trend that holds in all three runs isn't caused by either of those.

## What changed in how it runs and is analysed
- **All three models now run interleaved in one process,** in a randomised block design. Any machine slowdown affects every model equally. Speed probes record drift in `machine_drift.csv`.
- **Statistics are done per case:**
  - repeats are averaged within each case;
  - class-stratified bootstrap 95% CIs are computed over the 30 cases;
  - model comparisons use paired sign-flip tests.
- **Multiple comparisons:** a small primary family, fixed in advance (model pairs × d at N = 5,000 for runtime, held-out RMSE and reference Jaccard), is Holm-corrected. **This is what the paper should claim.** Everything else is descriptive.
- **Runtime scaling is now fitted,** not read off the graph. `runtime_scaling.csv` gives power-law exponents in N and d.
- **Reproducibility checks:**
  - seeds are derived per case;
  - full runs stop if package versions don't match `requirements-pinned.txt`;
  - model fingerprints must match across variants.
- **Size:** 3,000 timed explanations per model (9,000 in total), plus 240 reference explanations per model. Expected time for all three variants is about 3–4.5 hours (estimate).

## Why d = 50 was added
- The branch's reason: a **fourth d value** gives 20 design points (4 d × 5 N) for the runtime power-law fit, which leaves room to test whether the N exponent changes with d.
- The reasons we added today:
  - it is a deliberate **low-dimensional baseline**, so the paper can show quality degrading *from* a setting where LIME should work well;
  - it **never has a low sample-to-feature ratio** (at least 10 samples per feature);
  - it halves 100, is still 5× the 10 features LIME reports, and costs only about 6% extra run time.
- **For the paper:** keep "high-dimensional" claims to **100–500** and describe 50 as the baseline.
